# RECOVERY 44

기독교환경운동연대 44주년을 위한 2026년 활동 회고 인터랙티브 웹 경험입니다. 6개 PART·24개 장면, 실제 현장 사진·자료 이미지, 사용자 선택에 따른 4종 PNG 결과 카드로 구성했습니다.

## 실행

빌드·패키지 설치·API 키가 필요하지 않습니다. Python 3가 있는 환경에서:

```sh
cd /workspace/2026end
python3 -m http.server 4173 --bind 0.0.0.0
```

브라우저에서 서버의 4173 포트로 접속합니다. `file://`로 HTML을 직접 열면 JSON 로딩이 차단될 수 있으므로 HTTP 서버를 사용하세요. 외부 공개 시 이 폴더를 그대로 정적 호스팅하면 됩니다.

이 클라우드 작업은 이미 격리된 환경입니다. 기존 체크아웃을 사용하고, 사용자가 요청하지 않은 Git worktree를 만들지 않습니다. 새 작업에서 서버 프로세스는 다시 시작해야 합니다.

## 사용

- 좌우 화살표 키·하단 버튼·수평 스와이프로 이동합니다. 장면이 길면 세로 스크롤을 이용합니다.
- ‘여정의 지도’로 원하는 PART에 이동하고, 각 장면의 ‘현장의 기록’을 본문에서 바로 읽을 수 있습니다. 원문 출처는 데이터와 Scene Map에 보관합니다.
- 교회의 숲, 물줄기 연결 등은 상징적 참여입니다. 실제 서명·후원·식재 집계가 아닙니다.
- 마지막 4개 회복 중 하나를 선택하면 1080×1350 PNG 카드가 생성됩니다. 다시 선택하거나 처음부터 돌아갈 수 있습니다.
- 모바일 파일 공유 API를 지원하면 공유 시트를 사용하며, 지원하지 않으면 PNG 저장을 제공합니다. iOS에서는 다운로드 메뉴·파일 앱에서 이미지를 확인할 수 있습니다.

## 구조와 수정

`index.html`은 시맨틱 셸, `styles.css`는 반응형 디자인·전환, `app.js`는 장면 렌더링·참여·카드 생성입니다. 콘텐츠는 `data/scenes.json`, 이미지별 원본 파일명과 페이지는 `data/photos.json`, 구현 전 설계와 사실관계 판단은 [docs/SCENE_MAP.md](docs/SCENE_MAP.md)에 있습니다.

사진은 첨부 PDF에서 추출해 WebP로 최적화했습니다. 추출 이미지에는 현장 사진뿐 아니라 달력·모금 제작 안내도 포함되며 각 장면에서 구분합니다. PDF 원본은 이 소스에 중복 포함하지 않았습니다. 사진의 출처는 기독교환경운동연대의 제공 활동기록이며 권리 이전을 주장하지 않습니다.

한글 웹폰트는 Noto Sans CJK의 서브셋을 로컬 WOFF로 제공합니다. [폰트 라이선스](assets/FONT-LICENSE.txt)를 함께 배포하세요. 콘텐츠에 새로운 한글을 추가하면 해당 글자는 시스템 글꼴로 대체될 수 있습니다.

CDN 폰트와 분석·추적 도구는 사용하지 않습니다. 사진은 기본적으로 기기 안에서 처리하고, 참여자가 동의 후 보내기를 누른 완성 카드만 지정 Worker를 통해 운영자의 Dropbox에 전송합니다. HEIC/HEIF 변환기는 로컬 파일로 제공하며 필요할 때만 불러옵니다. 초기에는 현재 장면과 다음 장면 사진만 불러옵니다. 총 사진 용량 약 4.1MB, 로컬 폰트 약 120KB입니다.

## 2026-10-30 수정

이·취임식 버튼명과 풍천리·수유동·기후정의연합예배 문구를 수정했습니다. 이·취임식 사진은 PDF 원본 픽셀을 무손실로 다시 추출하고, 원본 비율과 최대 표시 폭을 유지해 확대와 잘림을 줄였습니다. PDF 자체가 512×341이므로 고해상도 원본으로 대체한 것은 아닙니다.

산황산 선택지마다 다른 현장 사진을 표시하며, 한국 교회의 환경주일 실천은 교회 선택에 따라 사진과 현장의 기록이 함께 바뀝니다. 순천승산교회 사진은 6월 PDF p10의 실제 현장 사진으로 바로잡았습니다. 걷기기도회 사진 아래 일정 자막을 없애고, 녹색교회 사진 위치를 조정했습니다. 생태달력 기록 아래에는 새 창으로 열리는 신청 링크를 추가했습니다. 탄소배출량 팝업의 기후정의 설명을 보완하고, 행진 배경의 색상 덮개·밝기 필터 및 네팔 대홍수 장면의 선택 버튼을 제거했습니다. 단일 HTML도 동일하게 반영했으며 크기는 약 5.8MB입니다.

## 내 사진으로 회복 카드 만들기

회복 유형을 선택한 결과 화면에서 **사진 찍기** 또는 **사진 선택하기**를 누르면 내 사진에 회복 문구와 프레임을 얹습니다. 카드 미리보기에서 사진을 직접 끌거나 확대·축소해 구도를 맞춘 뒤 **나의 회복 카드 저장 및 보내기**이나 **카드 공유하기**를 이용하세요. 출력 크기는 1080×1350입니다. 사진은 카드 영역을 채우도록 표시되어 가장자리가 일부 잘릴 수 있습니다.

‘사진 찍기’는 지원하는 모바일 브라우저에서 카메라 촬영을 요청합니다. 기기·브라우저에 따라 파일 선택 화면으로 열릴 수 있습니다. 선택한 원본은 브라우저 안에서만 처리합니다. 참여자가 별도 동의하고 보내기 버튼을 누른 완성 카드만 운영자의 Dropbox에 저장합니다. 다른 회복 유형을 고를 때는 같은 사진과 위치를 유지하고, 기본 사진으로 돌아가기·처음부터 다시 걷기·새로고침 시 선택 사진을 비웁니다. HEIC/HEIF가 브라우저에서 바로 열리지 않으면 로컬 변환기를 사용합니다. 변환이 불가능한 파일은 JPG·PNG·WebP로 저장한 뒤 다시 선택하세요. 실제 iOS/Android 카메라 및 OS 공유 시트는 별도 실기기 확인이 필요합니다.

검증: 로컬 서버 실행 후 `python3 tests/photo_card_check.py`. 임시로 생성한 세로·가로 이미지를 사용해 사진 입력·위치 조절·PNG 픽셀·프레임·4개 유형·취소·실패·초기화·동의 전 전송 금지와 동의 후 모의 전송을 분리 소스와 단일 HTML에서 검사합니다.

## 휴대폰 가로 보기

휴대폰에서는 가로 화면으로 표시합니다. 세로로 들고 있어도 별도 안내 화면 없이 페이지 자체가 90도 돌아간 상태로 보이며, 휴대폰을 옆으로 돌려 읽을 수 있습니다. 실제 회전 전후에 현재 장면·사진 선택·개인 사진 카드 상태를 유지합니다. 짧은 가로 화면에서는 필요한 내용을 세로로 스크롤해 읽습니다. 팝업도 같은 방향으로 표시하며 데스크톱의 세로 창은 회전시키지 않습니다.

`python3 tests/orientation_check.py`로 회전 표시와 실제 회전 전후 상태·팝업·탭·카드 저장을 확인합니다. 기존 모바일 검사도 844×390 및 568×320 가로 화면으로 갱신했고, 개인 사진 검사는 가로와 세로 상태를 모두 포함합니다. Chromium의 터치 화면 에뮬레이션으로 확인했으며 iOS/Android 실기기의 브라우저 도구 모음·노치·회전 잠금 조합은 별도 확인이 필요합니다.

## 휴대폰 읽기·스크롤 보정

첫 화면의 RECOVERY 글자 간격을 정상 간격으로 바꾸고 제목·설명·시작 버튼이 서로 겹치지 않게 배치했습니다. 본문과 팝업은 손가락을 위아래로 움직여 끝까지 읽을 수 있으며, 옆으로 표시된 세로 화면에서도 화면 방향에 맞춰 스크롤됩니다. 좌우 장면 이동과 사진 필름의 별도 조작은 유지합니다. 행진 장면은 제목 옆에 참여 버튼·물줄기·참여 숫자를 모아 작은 휴대폰 화면에서도 처음부터 조작할 수 있게 했습니다.

`python3 tests/mobile_reading_check.py`는 실제 Chromium 터치 입력으로 긴 본문 끝까지 이동, 마지막 문장이 하단 내비게이션 위에 보이는지, 팝업 스크롤, 첫 장 겹침과 행진 참여 버튼/숫자 노출을 검사합니다. 분리 소스와 단일 HTML, 두 크기의 실제 가로/옆으로 표시된 세로 상태를 모두 포함합니다.

## 저장·보내기 동의 및 수동 재시도

좌표 격자와 위치 슬라이더는 삭제하고, 카드 미리보기의 사진을 직접 움직여 구도를 조절합니다. ‘사진 찍기’와 ‘사진 선택하기’는 초록색 버튼이며 사진 수·형식·보관 설명과 결과 화면의 2026/2027 문구는 화면에서 제거했습니다. 15MB 및 형식 검사는 유지합니다.

‘나의 회복 카드 저장 및 보내기’를 누르면 동의 팝업이 열립니다. **동의해야 기기에 PNG를 저장하고 동일 카드를 운영자의 Dropbox에 전송**합니다. 동의하지 않거나 팝업을 닫으면 저장·전송하지 않습니다. 카드 공유 역시 동의 후 동작하고, Web Share를 지원하지 않는 경우에만 PNG로 저장합니다.

- API 주소: `https://recovery44-upload.kh3188.workers.dev/`
- 기존 계약 유지: `POST`, `FormData`의 `file` 필드 한 개, 1080×1350 완성 PNG
- 실패: ‘사진을 전송하지 못했습니다.’ 및 API 오류 상세와 **다시 시도** 표시
- 재시도: 직전 전송의 **동일 Blob 객체**를 사용. Canvas/PNG를 다시 만들거나 파일을 다시 저장하지 않음
- 재전송 중: 버튼 비활성화·‘다시 전송하는 중입니다…’, 자동 재시도 없음
- 성공: ‘전송 완료 ✓’ 및 전송 카드 미리보기
- 새 사진 선택/카드 재생성: 이전 실패 Blob·전송 상태·동의를 초기화
- Dropbox 인증정보는 프런트엔드에 없음. 기존 Worker Secret 사용 유지

## Worker 파일명 수정본 — 수동 반영

[붙여넣기용 전체 Worker](docs/worker/recovery44-upload.mjs)를 Cloudflare Edit code에 복사해 사용합니다. **이 파일은 검토용 사본이며 자동 배포하지 않습니다.** 사용자가 제공한 실제 정상 배포본에서 파일명 생성 블록만 변경했습니다. CORS·Secret·파일 검증·Dropbox API 호출·`/uploads/`·`mode: add`·`autorename: true`·`mute: false`는 그대로입니다.

파일명은 Worker가 `Asia/Seoul` 기준으로 `RECOVERY44_YYYYMMDD_HHMMSS_XXXX.png`를 만들며, XXXX는 A–Z 및 0–9의 무작위 4자리입니다. 브라우저가 보내는 `RECOVERY44_card.png`는 최종 저장 파일명에 사용하지 않습니다. 드물게 같은 이름이 발생하면 Dropbox autorename 안전장치가 처리합니다. 기존 `DROPBOX_ACCESS_TOKEN` Secret을 계속 사용하며 값을 소스에 넣지 않습니다.

사용자가 실제 모바일 GitHub Pages → Worker → Dropbox 저장 성공을 확인했습니다. 이후 클라우드 환경의 Worker 403을 해결하거나 우회하지 않으며, API·CORS 설정도 바꾸지 않습니다. 이번 검증은 전부 로컬/모의 요청이며 실제 Dropbox 최종 검증 및 Worker 반영은 사용자가 수행합니다.

검사: `python3 tests/upload_check.py`, `python3 tests/photo_card_check.py`, `node tests/worker_filename_check.mjs`. Worker 검사도 실제 Dropbox 대신 모의 fetch로 요청 구조·한국 시간·랜덤 코드·autorename을 확인합니다. HEIC 변환기는 기존 assets/vendor 및 단일 HTML에 그대로 포함합니다.

## 카드 사진 직접 편집

사진을 선택하면 카드의 사진 영역을 손가락이나 마우스로 끌어 이동할 수 있습니다. 휴대폰은 두 손가락을 벌리거나 모아 확대·축소하고, PC는 마우스 휠을 사용합니다. 확대/축소 버튼과 ‘원래대로’도 제공합니다. 사진 전체가 보이는 최소 비율부터 기본 크기의 400%까지 조절하며 프레임과 회복 문구는 움직이지 않습니다.

카드에 초점을 두면 방향키로 이동(Shift는 큰 간격), +/−로 확대·축소, Home으로 원래 구도를 복원할 수 있습니다. 사진을 탭만 했을 때에는 기존 PNG를 유지하고, 실제 편집할 때만 재생성합니다. 드래그·핀치 중에는 가벼운 미리보기만 그리고 손을 놓을 때 완성 PNG를 생성합니다. 편집 중에는 저장/전송을 잠시 막으며, 구도를 바꾸면 이전 실패 Blob은 초기화됩니다. 다른 회복 유형으로 바꾸어도 구도를 유지합니다.

버튼은 ‘나의 회복 카드 저장 및 보내기’이며, 저장/전송 동의 문구는 ‘회복 카드를 이 기기에 저장하고 기독교환경운동연대에게 전송,보관하는데 동의하시나요?’입니다. 기존 동의 거부 시 저장 금지, 동일 PNG 수동 재시도, HEIC 처리와 API 주소·FormData/file은 유지합니다.

검사: `python3 tests/photo_gesture_check.py`. 실제 Chromium 터치·마우스 입력으로 가로 및 옆으로 표시된 세로 화면에서 드래그·두 손가락 확대/축소·휠·키보드·버튼·최소/최대 비율·구도 유지·스크롤/장면 이동과의 충돌 및 PNG 생성 횟수를 검사합니다. 실제 모바일 기기의 브라우저 제스처는 사용자의 최종 확인이 필요합니다.
